# Combine service categories with privacy-safe descriptions

Accepted in the October 24, 2026 schema interview. Canonical service facts should combine a controlled category with a privacy-safe description of the work, retaining useful detail for answers to “what was done?” Original free text remains private, and the derivation of the normalized description must be traceable.

The current “gate fix” to “other” mapping loses useful service detail. A gate-repair category and safe description illustrate the intended outcome; the vocabulary and description-generation policy remain to be decided. Directly exposing source notes is not an acceptable alternative.

This is an accepted design decision, not an implemented change.

The operator subsequently accepted descriptions generated from recognized service facts and approved wording. An unrecognized service receives an honest generic description and an unmapped-service issue; raw text is neither copied into public output nor used to guess unsupported details.
